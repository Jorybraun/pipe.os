## What this job is

PIPE has two drifts that the code and the research specification have grown apart on, and they are halves of one bridge. On the Role Discovery side, the design-thinking intake interview produces a rich Knowledge State JSON per `migration/dersign-thinking.md` Part 8 — six domains, laddering chains, per-turn energy signals, structured stories, and per-stakeholder perspectives from the multi-stakeholder flow in ADR-028. In code, synthesis flattens that Knowledge State into an 8-field `CandidatePersona` at `workers/api/src/types.ts:223`, and every downstream consumer (culture interview, challenge generation, scorer, repo discovery) reads only the flattened output. The Knowledge State is persisted but nothing reads it. On the repo side, the crawler completed Pass 1 and Pass 2 entirely deterministically (zero LLM calls) and `workers/api/src/lib/repoDiscovery/matchRepos.ts` is a SQL CTE join on `persona.mustHaveSkills[]` — no reasoning layer between the SQL candidates and final role-fit ranking. The two drifts compound: even if Role Discovery produces a richer Role Context Document, nothing on the repo side can reason over it, and even if the repo side gains an AI enrichment pass, there is no stable input contract for it to consume. ADR-036 defines both halves of the data contract so they land together.

A two-day research run closed the research side of this work on 2026-04-10. Four parallel researcher agents produced 84 cited sources, a Lead-written synthesis brief, a verifier citation + URL pass, and a reviewer evidence-integrity pass with verdict PASS WITH NOTES (0 FATAL, 3 MAJOR patched before delivery, 5 MINOR accepted). ADR-036 was drafted the same day, capturing the full architectural decision with TypeScript schema sketches, SQL DDL for three new D1 tables, model routing rules, a schema migration plan, and a four-phase rollout. The founder then asked for this handoff so the implementation phase can resume cleanly from cold.

**Nothing has been built yet.** The entire output of this research run is documentation. The implementation begins when the founder picks the sequencing question at the bottom of this file.

## Phase 1 implementation decisions (2026-04-10, post-kickoff)

These decisions were made during the Phase 1 kickoff conversation and resolve internal contradictions in ADR-036. They supersede the corresponding ADR text; update ADR-036 when it transitions from Proposed to Accepted.

**Verifier transport — Gemma 4 26B, not Haiku.** ADR-036 § Model routing table says "RCD synthesis verification pass | Claude Haiku 4.5 (via Agent tool) | Anthropic | Offline." Phase 1 step 5 says `verifyRcd.ts` is a Worker module called inline at synthesis time. Those two statements are incompatible — "via Agent tool" is the offline Claude Code path and cannot run inline in a Worker. The research brief itself (R1 §1.2 Layer 3) frames Haiku as "appropriate given the offline, non-latency-sensitive nature" — a cost recommendation for offline runs, not a mandate. The research was written assuming synthesis would run offline on Sonnet 4.6 via the Anthropic API; ADR-036 moved synthesis to Gemma on Workers AI for cost/latency and left the verifier stranded on an offline model. Resolution: the verifier runs on Gemma 4 26B via the existing `CloudflareAIProvider`. No new `AnthropicProvider`, no new `ANTHROPIC_API_KEY` secret, no new Worker egress path. The model-family independence rule cited in the ADR applies to the Repo half (Haiku enrichment / Gemma rerank) and to ADR-032's implementer/classifier per-turn hot path — it is not cited anywhere in the research brief for the synthesis/verifier pair.

**The verifier is mostly deterministic TypeScript, not an LLM call.** Per the research brief, the verifier's job is three checks: (1) every `attribute_quote` is a verbatim substring of its referenced transcript exchange — pure string operation, no model needed; (2) every `energy_signal: HIGH` has a verbatim lexical marker from a fixed vocabulary — regex against a word list, no model needed; (3) every `consequence` is derivable from the quoted turn alone — this is the only LLM-dependent check. So `verifyRcd.ts` runs (1) and (2) in plain TypeScript and calls Gemma 4 26B only for the per-chain entailment residue in (3). Cost is minimal. Failure modes: chains that fail (1) or (2) are flagged as unsupported and the cell's `confidence` drops to `low`; chains that fail (3) are flagged for recruiter review. No automatic regeneration in Phase 1 — flag-then-surface is sufficient.

**Constrained decoding — schema-in-prompt only, no grammar constraints.** Per the research brief (R1 §Layer 2 and §Practical note for PIPE): "Workers AI (Gemma 4 26B) does not natively expose grammar-constrained decoding. The Anthropic API supports structured outputs via `response_format: { type: 'json_schema' }` — this is effectively constrained decoding at the API level." Since synthesis runs on Gemma on Workers AI per the ADR routing table, real constrained decoding is not available. Phase 1 ships with the full RCD JSON schema embedded in the synthesis system prompt + strict parse-time validation + one conditional retry on schema-violating cells. This is an explicit deviation from ADR-036 step 4 ("Constrained decoding wiring — Anthropic API `response_format: json_schema`"). Log in STRATEGY.md Decision Log at commit time.

**No new secrets or transports added in Phase 1.** The two decisions above together mean Phase 1 adds zero new dependencies — no `AnthropicProvider`, no new env vars, no new egress path, no new npm package. Phase 1 is pure D1 + existing Workers AI binding + existing `CloudflareAIProvider`. If a later phase needs Anthropic API access (for BARS override generation on Sonnet 4.6, for example), that's a Phase 2+ concern and gets its own transport decision.

## Guardrails you must not drop

These are the load-bearing rules from the research that will cause bugs, compliance exposure, or silent drift if you forget them. Surface them before writing code for the relevant phase.

**Versioning precondition is not optional.** The RCD carries `validation_metadata` and the RUC carries `rcd_version` + `signals_version`. No schema change ships without bumping the version column and recording it. Without these, old cohorts silently mix with new ones after schema evolution and every future comparison becomes confounded. This blocks the entire staged validation ladder.

**Bottom-up synthesis ordering is load-bearing.** The synthesis prompt must instruct the model to extract `attribute_quote → consequence → value` in that order, never the reverse. Reversing causes value projection — the model leads with generic values and back-fills evidence to fit. This is the top failure mode in the research.

**Model-family independence between Pass 3 and the runtime rerank.** Pass 3 uses Haiku 4.5 for offline signal extraction. The runtime rerank uses Gemma 4 26B. Never Haiku reranking Haiku-generated signals — the rerank must have an independent read on the substrate it consumes, consistent with the ADR-032 implementer/classifier separation principle. If you slot in a different model for either half, verify it's a different family.

**OCAI must use Current-culture framing, not Ideal.** Harver uses the Ideal framing as a candidate screen. Heritage et al. 2014 show the Ideal framing has no significant relationship with job satisfaction. PIPE uses Current-culture framing exclusively, and the profile describes *the team* as reported by HM and TM — never the candidate. This is a validity requirement, not a stylistic choice.

**Dealbreakers are HITL-only.** Never auto-fail. The scorer raises a flag; the recruiter reviews; the recruiter either confirms (creating the audit trail) or overrides. Every dealbreaker record carries `jobRelatednessNote` + `jobRelatednessStrength` to pre-populate the Griggs business-necessity defense. Auto-fail mechanisms are indefensible under Griggs, the Uniform Guidelines four-fifths rule, EEOC v. iTutorGroup, and EU AI Act Article 14 (applicable 2 August 2026). Red flags are advisory-only and never block advancement.

**Probe bank enrichment is role-setup-time, never per-candidate.** Per-candidate dynamic probe generation fails NYC Local Law 144 auditability and EU AI Act Article 14 interpretability. All probes come from a finite, versioned, recruiter-approved bank keyed by `role_context_id`. Same rule applies to BARS overrides.

**Synthesis tone is constructive.** Per the feedback memory "synthesis must be constructive, never roast the user's team" — the Knowledge State can contain blunt observations, but the narrative/summary fields the recruiter sees must be diplomatic.

**Per-stakeholder preservation, never averaging.** Conway & Huffcutt show supervisor-peer ρ=.34, which means 89% of the variance is source-unique. Averaging two stakeholders' positions discards nearly all the information. The three-tier aggregation protocol is non-negotiable: domain-authoritative anchors, per-source preservation on shared domains with `conflict_flag`, explicit-formula aggregates only on genuine consensus. **Disagreement is its own category, not a midpoint.**
