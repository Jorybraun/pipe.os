### 1. `culture.rest.test.ts` — `initialises dimensionCoverage to zero for all dimensions`

**Location:** `workers/api/src/routes/screening/__tests__/culture.rest.test.ts:98-103`

**Root cause:** The test calls `startCultureInterview()` (defaults to `profile_builder` mode) but iterates over `COMPETENCY_DIMENSIONS` (`ownership`, `collaboration`, etc.). `profile_builder` mode initializes `dimensionCoverage` with `PROFILE_PROBE_DIMENSIONS` (`career_history`, `behavioral_depth`, etc.). Therefore `dimensionCoverage['ownership']` is `undefined`, not `0`.

**This is a pre-existing test bug** — the old `startCultureInterview` also returned `emptyProfileCoverage()` for the default mode, so this test would have failed before the redesign. It should check `PROFILE_PROBE_DIMENSIONS` when mode is `profile_builder`.

**Fix:** Update the test to pass `{ mode: 'role_fit' }` to `startCultureInterview()`, or iterate over `PROFILE_PROBE_DIMENSIONS` for the default call.

## Architecture Notes for Integrators

### Phase Flow

```
consent → [START] → rapport_building (2 turns) → probing → [DRILL] → drilling → probing → wrap_up (2 turns) → scoring → complete
```

### Drilling Behavior
- Probes are allowed in `rapport_building`, `probing`, and `drilling` phases
- When the LLM says `probe_needed`, the orchestrator:
  1. Dispatches `DRILL` action (sets `currentDrill`)
  2. Dispatches `ADVANCE_PHASE` to `drilling`
  3. Appends probe turn and returns `action: 'probe'`
- When the LLM says no probe needed while in `drilling`, the orchestrator forces `ADVANCE_PHASE` back to `probing`
- `buildPhaseDirective` returns `probing` when `currentDrill.attempts >= maxAttempts`

### Coverage Sync
- The reducer recomputes `CoverageState` after every `ANSWER` and `DRILL_ANSWER`
- `scratchpad.dimensionCoverage` is overwritten with `depthScore` values from `CoverageState.dimensions`
- This means `pickNextQuestion` and `pickNextProfileProbe` now receive continuous depth scores (0–2) instead of integer counts
- The existing selector math (`1 / (coverage + 1)`) works correctly with depth scores

### Generative Questions (gen-*)
- `cultureAgent.ts` includes minimal synthetic question resolution for `gen-*` IDs
- Full generative planner integration is **not** included in this refactor — it belongs to the prompt-agent / integration scope
