## Summary
Fixed critical WebRTC connection failure in video interview feature. Root cause was three compounding bugs: auth asymmetry preventing signal delivery, auto-accept causing premature UI state changes, and missing connecting phase UI. Also fixed inverted drag positioning on the floating PiP component.

## Problem Statement
After recruiter clicked START_CALL and candidate clicked ACCEPT, both users got stuck showing "CONNECTING..." indefinitely. Console showed `Variable 'payload' has an invalid value` errors. GraphQL mutations successfully created ICE_CANDIDATE signals but recruiter's subscription never delivered the candidate's ANSWER/ICE signals.

## Root Causes

### 1. Auth Asymmetry (P0 - Blocking)
**Issue:** Recruiter's observeQuery subscription never received candidate's ANSWER or ICE_CANDIDATE signals.

**Cause:** Candidate creates signals via `apiKey` auth (no Cognito owner), but VideoSignal schema only had `allow.owner()` for authenticated users. AppSync authorization checks happen per-record BEFORE subscription filters, so signals without matching owner were silently dropped.

**Impact:** Impossible to establish WebRTC connection. Recruiter never knew candidate answered the call.

### 2. Auto-Accept Bug (P1 - UX)
**Issue:** Widget disappeared immediately after candidate accepted call, before connection established.

**Cause:** Dispatch handler in VideoShell immediately called `acceptCall()` + `markActive()` when OFFER signal arrived, flipping session status to ACTIVE before user clicked ACCEPT button.

**Impact:** Confusing UX where incoming call widget vanished instantly.

### 3. Silent ACCEPT Button (P1 - UX)
**Issue:** ACCEPT button did nothing when clicked.

**Cause:** Button was wired to `onCall` → `handleCall` → `startCall()` which has `if (role !== 'RECRUITER') return` guard.

**Impact:** Candidate had to refresh page to retry accepting call.

### 4. Connecting Void (P2 - UX)
**Issue:** After clicking ACCEPT, neither widget showed any status during ICE negotiation.

**Cause:** Once `markActive` flipped status to ACTIVE, none of the VideoWidget conditional render branches matched (`waiting`, `calling`, `incoming`, `connected` all false).

**Impact:** Users saw nothing during 2-3 second ICE negotiation phase.

### 5. Inverted Drag (P3 - Cosmetic)
**Issue:** Dragging PiP component moved it in opposite direction of mouse movement.

**Cause:** Position stored as `left` coordinates but style used `right: position.x`.

**Impact:** Confusing drag behavior.

## Technical Details

### Auth Rule Before/After
```typescript
// Before
VideoSignal: a.model({
  // ...
}).authorization(allow => [
  allow.owner(),
  allow.publicApiKey().to(['create', 'delete'])
])

// After
VideoSignal: a.model({
  // ...
}).authorization(allow => [
  allow.owner(),
  allow.publicApiKey().to(['create', 'delete']),
  allow.authenticated().to(['read'])  // ← NEW
])
```

### Deferred Accept Pattern Before/After
```typescript
// Before - Auto-accept in dispatch handler
case "OFFER":
  await acceptCall(JSON.parse(signal.payload));
  await markActive();
  break;

// After - Store for user action
case "OFFER":
  pendingOfferRef.current = JSON.parse(signal.payload);
  setHasPendingOffer(true);
  break;

// And separate handler
const handleAccept = async () => {
  if (!pendingOfferRef.current) return;
  if (!localStream) {
    error = await ensureCameraReady();
  }
  await acceptCall(pendingOfferRef.current);
  await markActive();
};
```

### Connecting State Logic
```typescript
const isConnecting = 
  sessionStatus === 'ACTIVE' && 
  !isConnected && 
  !isEnded;
```
