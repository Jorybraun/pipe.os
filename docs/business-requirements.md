# Pipe — AI-Native Developer Interview Platform

## Business Requirements Prompt

You are building **Pipe**, a modern technical interview platform that embraces AI as a core part of the developer workflow. Unlike traditional platforms that try to prevent AI use, Pipe **evaluates how effectively developers work with AI** — because that's the reality of modern software development.

---

## Core Philosophy

Traditional coding interviews are broken. AI tools can trivially solve standard algorithm questions, making them meaningless. The most successful developers today don't just write code — they:
- Ask thoughtful clarifying questions
- Use AI strategically for well-defined subtasks while maintaining control
- Critically review and improve AI-generated code
- Demonstrate strong debugging skills when AI solutions have issues

Pipe evaluates these real-world skills.

## Interview Pipeline

The platform supports a configurable multi-stage interview pipeline. The default stages are:

### Stage 0: AI Screening Call
- **Type**: Voice (async or scheduled)
- **Duration**: 15 minutes
- **Purpose**: Automated phone screen with AI interviewer
- **Evaluates**: Basic qualifications, communication, enthusiasm
- **Auto-generated from**: Role requirements, job description

### Stage 1: AI Collaboration Assessment
- **Type**: Coding (async)
- **Duration**: 45-60 minutes
- **Purpose**: Evaluate how effectively candidates leverage AI tools
- **Format**: Candidate receives a feature specification and must use an embedded AI assistant to implement it. All prompts, iterations, and refinements are logged.
- **Scoring Dimensions**:
  - Prompt Clarity (1-10): Were instructions clear and specific?
  - Iteration Efficiency (1-10): How many attempts to reach quality output?
  - Critical Review (1-10): Did they catch and fix AI mistakes?
  - Strategic Decomposition (1-10): Did they break complex tasks into AI-appropriate subtasks?
- **Auto-generated from**: Role tech stack, required skills, seniority level

### Stage 2: Code Review Challenge
- **Type**: Review (async)
- **Duration**: 30-45 minutes
- **Purpose**: Test ability to identify bugs, security issues, and suboptimal patterns in AI-generated code
- **Format**: Present 3-5 code snippets "generated by AI" with intentional issues:
  - Subtle logic bugs
  - Security vulnerabilities (SQL injection, XSS, timing attacks)
  - Performance anti-patterns
  - Edge case failures
  - Incorrect assumptions
  - Race conditions
  - Memory leaks
- **Display**: Actual code with syntax highlighting, line numbers, clickable bug indicators
- **Scoring Dimensions**:
  - Bugs Found (40%): Number of issues correctly identified
  - Severity Assessment (25%): Correctly prioritizes critical vs low issues
  - Fix Quality (25%): Proposed fixes are correct and complete
  - False Positives (10%): Doesn't flag correct code as buggy
- **Auto-generated from**: Role tech stack (Python/JS/Go/etc), domain (backend/frontend/infra), seniority

### Stage 3: Feature Planning & Prompt Design
- **Type**: Planning (async)
- **Duration**: 30 minutes
- **Purpose**: Evaluate architectural thinking and ability to translate requirements into AI-actionable prompts
- **Format**: Given a product requirement document, create:
  - System architecture diagram
  - Component breakdown
  - Series of prompts to implement each component
  - Expected outputs from each prompt
- **Scoring Dimensions**:
  - Architectural Soundness
  - Prompt Strategy (specificity, context provision, iterative approach)
  - Anticipated edge cases and error handling
- **Auto-generated from**: Role level, domain, team structure

### Stage 4: Live Voice Interview
- **Type**: Voice (scheduled)
- **Duration**: 30-45 minutes
- **Purpose**: Assess communication, problem-solving under pressure, and real-time AI collaboration
- **Format**: AI interviewer conducts technical discussion including:
  - System design questions
  - Behavioral questions
  - Live coding with AI assistance
  - Debug a failing system together
- **Scoring Dimensions**:
  - Communication Clarity (25%)
  - Technical Depth (35%)
  - Problem Solving (25%)
  - Culture Fit (15%)
- **Auto-generated from**: Role requirements, team values, technical focus areas

### Stage 5: Human Panel Interview
- **Type**: Panel (scheduled)
- **Duration**: 60 minutes
- **Purpose**: Final validation with human interviewers
- **Format**: Review all previous stage outputs, deep-dive on interesting decisions, culture fit, Q&A
- **Not auto-generated**: Configured by hiring manager

## Agentic Pipeline Builder

### Concept
Instead of manually configuring each interview stage, users interact with an **AI agent** that helps them design the entire hiring pipeline through conversation. The system auto-generates interview content based on the role requirements.

### User Flow

1. **Pipeline Creation**
   - User describes the role: "Senior Software Engineer, backend focus, Python/Go"
   - AI generates a suggested pipeline with 5 stages
   - AI explains what each stage tests and why it's relevant

2. **Stage Editing**
   - User clicks a stage to edit
   - Left panel transforms into a **stage-specific design agent**
   - Right panel shows generated content (code, questions, rubrics)

3. **Content Generation**
   - Based on role + stage type, AI auto-generates:
     - Code review challenges with planted bugs
     - Voice interview questions with follow-ups
     - Scoring rubrics with weighted dimensions
   - User can ask agent to modify: "Add more security-focused bugs" or "Make it harder"

4. **Contextual Agents**
   - Each stage type has a specialized agent:
     - **Code Review Designer**: Understands bug types, severity, code patterns
     - **Voice Interview Designer**: Understands question types, follow-ups, behavioral assessment
     - **AI Collab Designer**: Understands prompt evaluation, iteration patterns
   - Agents provide relevant suggestions based on context

### UI Structure

```
┌─────────────────────────────────┬───────────────────────────┐
│         LEFT PANEL              │       RIGHT PANEL         │
│        (Contextual)             │      (Stage Config)       │
│                                 │                           │
│  Default: Pipeline Builder AI   │  Default: Stage List      │
│  On edit: Stage Designer AI     │  On edit: Stage Content   │
│                                 │                           │
│  - Chat interface               │  - Code blocks w/ bugs    │
│  - Quick replies                │  - Question cards         │
│  - Context-aware help           │  - Rubric editors         │
└─────────────────────────────────┴───────────────────────────┘
```

### Key Behaviors

1. **Auto-Generation**: Questions, code, rubrics generated from role requirements — not manual entry
2. **Contextual Transformation**: Left panel becomes a specialized agent when editing a stage
3. **Rich Content Display**: Code review shows actual code with syntax highlighting and bug annotations
4. **Agentic Refinement**: User asks agent to modify content, agent updates right panel

## Code Review Stage Requirements

When a user selects "Code Review" stage, the system should:

### Generate Code Challenges
- Based on role tech stack (Python, JavaScript, Go, etc.)
- Include 2-4 code snippets with intentional bugs
- Each snippet has:
  - Title and description
  - Language badge
  - Difficulty rating
  - Time limit
  - Line-numbered code with syntax highlighting

### Plant Realistic Bugs
Bug types to include:
- **Security**: SQL injection, XSS, CSRF, timing attacks, weak hashing, hardcoded credentials
- **Logic**: Off-by-one errors, race conditions, null handling, incorrect comparisons
- **Performance**: N+1 queries, memory leaks, inefficient algorithms, connection leaks
- **Edge Cases**: Empty inputs, boundary conditions, unicode handling

Each bug has:
- Line number
- Type (security/logic/performance/edge_case)
- Severity (critical/high/medium/low)
- Title and description
- Hint for candidates (optional)
- Expected fix

### Display Bug Annotations
- Toggle to show/hide bug locations
- Click line to expand bug details
- Color-coded by severity:
  - Critical: Red
  - High: Orange
  - Medium: Yellow
  - Low: Blue

### Auto-Generate Rubric
Based on the bugs planted:
- "Security Bugs Found" (40%)
- "Severity Assessment" (25%)
- "Fix Quality" (25%)
- "Code Quality Issues" (10%)

## Voice Interview Stage Requirements

When a user selects "Voice Interview" stage, the system should:

### Generate Questions
Based on role and seniority:
- 4-6 questions per interview
- Mix of categories:
  - Technical Deep Dive
  - System Design
  - Problem Solving
  - AI Collaboration
  - Behavioral

Each question has:
- Category label
- Main question text
- 2-3 follow-up questions
- Time limit (2-5 minutes)
- Rubric dimension and weight

### Auto-Generate Rubric
Weighted scoring dimensions:
- System Design (30%)
- Debugging Skills (25%)
- AI Proficiency (20%)
- Communication (25%)

### Display Format
- Question cards with expandable details
- Visual score distribution bar
- Color-coded rubric legend

## Profile Generation

As candidates progress through stages, the system generates a comprehensive profile:

### Data Sources
- Resume parsing (skills, experience, education)
- Screening call transcript
- AI collaboration prompts and iterations
- Code review findings
- Planning documents
- Voice interview transcript
- Human feedback

### Generated Profile Includes
- **Executive Summary**: 2-3 paragraph overview
- **Key Strengths**: Evidence-backed findings
- **Potential Concerns**: Areas to probe
- **Fit Scores**: Role fit, culture fit, growth potential (0-100)
- **Skill Analysis**: Claimed vs assessed proficiency
- **Interview Prep**: Suggested questions based on gaps
- **AI Recommendation**: Strong Yes / Yes / Maybe / No / Strong No

### Signals Detection
Throughout assessments, detect and surface:
- **Strengths**: Strong debugging, clear communication, efficient iteration
- **Concerns**: Accepted buggy output, vague prompting, missed security issues

## Technical Architecture

### Stack
- **Frontend**: Next.js (web), React Native (mobile)
- **Backend**: Node.js (API), Python (AI services), Go (code execution)
- **Database**: PostgreSQL (primary), Redis (cache), S3 (files), Vector DB (embeddings)
- **AI**: Claude API for all AI features
- **Voice**: ElevenLabs/Deepgram for TTS/STT, Twilio for calls

### Key Services
- **Auth Service**: User authentication and permissions
- **Core API**: Applications, candidates, pipelines
- **AI Service**: Profile generation, content generation
- **Voice Service**: Interview conducting, transcription
- **Code Execution**: Sandboxed code running
- **Scoring Engine**: Assessment evaluation

### Pipeline States
```
APPLIED → SCREENING → STAGE_1 → STAGE_2 → STAGE_3 → STAGE_4 → STAGE_5 → OFFER_PENDING → OFFER_SENT → HIRED
                ↓          ↓         ↓         ↓         ↓         ↓
             REJECTED   REJECTED  REJECTED  REJECTED  REJECTED  REJECTED

WITHDRAWN (from any non-terminal state)
```
